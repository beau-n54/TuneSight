## Objective

Implement platform-independent, deterministic and traceable relationships between existing owner-domain observations without creating causal explanation, a global diagnosis, recommendations or inspection advice.

## Scope

Conservative Correlation V1 consumes the persisted `engine_v2` analysis payload at page construction time. It derives qualified relationships from existing:

- event identifiers and authoritative event types;
- sample and RPM boundaries;
- pull windows;
- supporting channels;
- evidence statements;
- event confidence and severity;
- per-event explicitly ranked root causes;
- explicitly rejected causes; and
- Cross Reference identifiers.

Missing inputs remain missing. Same-log membership alone establishes no relationship.

## Prohibited Scope

WP-006.1 does not:

- generate Evidence;
- modify events or boundaries;
- generate or rank causes;
- average confidence;
- produce causal explanation;
- create a global diagnosis;
- recommend action;
- establish inspection priority;
- change Reasoning or Cross Reference;
- modify Vehicle Identity, Knowledge or Comparison;
- change persistence or database schema; or
- introduce platform-specific correlation logic.

## Output Contract

Each `CorrelationGroup` preserves:

- stable group identity;
- relationship type;
- contributing event IDs;
- contributing pull IDs where deterministically resolvable;
- shared family or cause identity where supplied;
- shared supporting channels;
- evidence references;
- contradiction references;
- dependency classification;
- categorical correlation strength;
- unresolved limitations;
- provenance; and
- applied rule identifiers.

Correlation strength is categorical and remains separate from event confidence, root-cause confidence and pull quality.

## V1 Rules

### COR-V1-REPEATED-EVENT-TYPE

Distinct event IDs with the same authoritative event type establish a repeated pattern. The rule establishes repetition only and never establishes an underlying cause.

Three or more separate contributing pull regions produce `strong` repetition. Two produce `moderate` repetition. This categorical strength describes the repeated relationship, not diagnostic certainty.

### COR-V1-SHARED-SIGNAL-DEPENDENCY

Overlapping observations with a shared supporting channel are recorded as dependent evidence. Shared source telemetry is not counted as independent corroboration.

### COR-V1-SHARED-AUTHORITATIVE-CAUSE

Distinct events with the same explicitly `primary` owner-domain cause produce a shared-cause relationship. The relationship does not become a global diagnosis and does not alter the supplied cause confidence.

### COR-V1-CONTRADICTORY-CAUSE

When a cause is explicitly primary for contributing events and explicitly rejected by another event, the contradiction remains visible and the relationship strength becomes `contradictory`.

## WGDC Contract

Repeated `wgdc_saturation` events form `WGDC Control Saturation Pattern`.

The group preserves every event, pull relationship, supporting channel and evidence statement. It explicitly records that repetition does not establish the underlying mechanical or calibration cause.

No turbo, boost-leak, actuator, mechanical or calibration diagnosis is introduced.

## Presentation Contract

WP-011 displays the qualified Correlation output without recalculating it. The shared Engineering Inspection Surface presents:

- relationship label and type;
- categorical correlation strength;
- contributing event and pull counts;
- shared channels;
- supporting and contradicting evidence;
- unresolved limitation; and
- expandable provenance.

The surface explicitly states that Correlation does not establish a global diagnosis or inspection direction.

## Persistence

No migration, schema change or new dependency is required. Correlation is deterministically recomputed from the existing persisted analysis on every page construction, preserving refresh compatibility for existing records.

## Validation

Focused validation covers:

- repeated WGDC relationships;
- stable event and pull references;
- shared authoritative causes;
- unrelated same-log events;
- explicit contradictions;
- shared-signal dependency;
- mutation protection;
- confidence and rank preservation; and
- representative N54, B58 Gen1 and B58TU/Supra contracts using identical rules.

Authenticated runtime validation uses existing persisted analyses only.

## Known Limitations

- Existing events do not carry an explicit pull ID. Pull association is deterministically resolved from supplied event and pull sample boundaries.
- V1 does not correlate free-form evidence text semantically.
- Shared channels are classified as dependency rather than claimed as independent corroboration.
- Explanation remains responsible for causal meaning.
- Decision remains responsible for recommendations and inspection priority.
