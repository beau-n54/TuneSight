# WP-004.3.8 — Governed Engineering Evidence Authority and ROM-Layout Applicability

Status: implemented and locally validated. Founder Founder subsequently accepted and locally published exactly four current N54 ROM-layout relationships through TuneSight Governed Engineering Evidence. No production, runtime, origin, or Legacy publication exists.

## Authority pathway

TuneSight preserves two non-equivalent authority pathways:

1. `external_source_authority` relies on authoritative source provenance.
2. `tunesight_governed_engineering_evidence` permits an authorised reviewer to accept a technically sufficient package when original source authority is unavailable, provided the limitation is disclosed as **TuneSight-qualified through governed engineering Evidence**.

Technical sufficiency creates review eligibility only. It never creates a Decision Record, admission, or publication. A separate explicit authorised reviewer decision remains mandatory and must preserve the pathway, evidence threshold, limitations, reviewer authority, and provenance.

## Layered identity model

`RomLayoutIdentity` represents stable ROM/software and calibration-layout identity. It binds software identifiers, ECU/DME family, binary length, container constraints, internal markers and exact offsets, calibration address space, Definition-compatible address range, XDF-side identities, and evidence provenance. It is deliberately narrower than engine family and deliberately broader than one calibration-content artifact.

`EngineeringBinaryIdentity` remains the exact instance identity. Each original, stock candidate, modified, or MapSwitch artifact keeps its own SHA-256 digest and source role. Definition applicability may therefore bind:

`Definition Set Revision ↔ ROM Layout Identity`

while every extracted value continues to bind:

`Definition Revision + exact Engineering Binary digest + raw offsets`

The existing exact-binary proposal, decision, and publication registry remains valid. ROM-layout qualification is an extension layer; it does not rewrite or silently migrate existing relationships.

## Evidence threshold

A governed review package is sufficient only when it binds the exact XDF Source Artifact and Definition Set Revision and establishes all of the following:

- explicit XDF identity corresponds to the proposed ROM layout;
- deterministic structural interpretation succeeds;
- at least one Definition is extraction-capable and every attempted extraction-capable Definition succeeds against the exact binary evidence;
- two or more distinct binary digests satisfy the same length, container, ROM/software identity, internal-marker, and exact-marker-offset constraints;
- at least one wrong-layout negative control rejects a contradictory exact binary identity;
- direct identity contradictions are absent;
- representation conflicts and Stock Variant states are disclosed;
- current/Legacy classification, source provenance, authority pathway, and limitations are explicit.

Same size, engine family, directory, or filename prefix is never sufficient. Different calibration values do not defeat layout equivalence. MapSwitch remains a modified-role artifact and is never represented as stock.

## Assessment and provenance

The deterministic assessment distinguishes:

- `evidence_sufficient_for_governed_review` — technical threshold is complete; an authorised decision remains pending;
- `more_evidence_required` — required positive proof is incomplete;
- `technical_conflict` — direct identity, binding, or negative-control Evidence contradicts applicability;
- `invalid` — the package cannot be assessed.

Source provenance is independently classified as `authoritative` or `disclosed_non_authoritative`. The governed pathway can be technically reviewable with disclosed non-authoritative source provenance; it must never claim BMW, OEM, or original-XDF-author authority.

## Scaling and ambiguity

The contracts are family-generic and preserve multiple internal markers rather than selecting one. This supports future MG1 evidence containing alternative software/calibration identifiers, duplicate XDF sources, detector ambiguity, Stock Variant conflicts, or incomplete XDF-side identities. Those conditions remain visible and can require more Evidence or exceptional review. Family-specific marker collectors are permitted only where encoding genuinely differs.

Current and Legacy XDFs remain distinct Source Artifacts and Definition Set Revisions even when both may target one layout. Layout applicability never resolves contained Definition representation conflicts.
