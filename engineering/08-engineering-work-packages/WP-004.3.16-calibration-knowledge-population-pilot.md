# WP-004.3.16 — Calibration Knowledge Population Pilot

## Authority and objective

This bounded pilot tests the repeatable path from real qualified BMW Calibration Definition Evidence to beginner-accessible Calibration Table education without weakening WP-004.3 admission, publication, applicability, conflict, provenance, or lifecycle authority.

TuneSight terminology distinguishes a governed **Definition**, an inspectable **Calibration Table**, a complete **Calibration**, and a flashed/programming-context **Map/Tune**. Authoritative source titles containing “Map” remain unchanged.

## Evidence census

IJE0S contains 739 qualified Workshop Definition instances and 249 source-supplied descriptions. Exact Definition identities/revisions, Definition Set membership, ROM Layout applicability, shapes, dimensions, axes, units, equations, conversion Evidence, source artifacts, and comparison Evidence are available. Canonical Calibration Knowledge, Engineering Assertion, admission, decision, publication, registry, lookup, provenance, conflict, and lifecycle contracts exist.

No populated production Calibration Knowledge Registry, exact semantic admission decision, publication receipt, or Workshop runtime Knowledge source exists. Analysis XDF cross-references are inferred/provisional. General automotive understanding, titles, addresses, numeric ranges, and similar names are not semantic authority.

## Schema reconciliation

The canonical model already represents identity, subsystem, Purpose, Engineering Intent, applicability, directional behaviour, operating conditions, relationships, assertions, provenance, authority, conflict, and limitations. The Workshop binding adapter projects those same governed assertions into `Understand` and `Engineering Detail`; it is not a Knowledge authority or registry.

The presentation adapter now preserves occurrence-scoped Workshop instance identities where one Definition revision has multiple legitimate occurrences. It also projects qualified directional effects, operating contexts, engineering considerations, axis meanings, related Tables, and telemetry relationships. Missing assertions create no prose.

## Scaling assessment

Deterministic batch stages can census Definitions, deduplicate identities/occurrences, preserve source descriptions and metadata, validate Definition Set/ROM applicability, construct candidate Evidence packages, detect repeated source representations, compare axis/unit/equation structures, run conflicts, and generate coverage reports. Explicit engineering/authority review remains mandatory for semantic equivalence, source trust, Purpose, Engineering Intent, subsystem classification, directional effects, relationships, telemetry relevance, limitations, admission decisions, and conflict resolution.

Scaling should proceed in reviewed cohorts: batch candidate construction, human authority decisions, deterministic publication, regression, and coverage audit. A published record may transfer only through explicitly governed applicability—not title similarity.

## Exclusions

No semantic record was published; no mass admission, recommendation, editing, binary reconstruction, runtime Dataset integration, Supabase change, deployment, or other BMW-family population was performed.
