# WP-004.3.7 — Applicability Publication and Qualified Relationship Registry

Status: controlled in-memory domain proof only; no real BMW relationship is admitted.

## Publication boundary

An immutable instruction can be constructed only from the exact accepted Applicability Decision, Proposal, and Authority Assessment revisions. It binds the exact Definition Set Revision, XDF Source Artifact, Engineering Binary digest, source role, provenance, expected registry Snapshot, and optional supersession target. Deferred, rejected, conflict, more-Evidence, stale, superseded, contradictory, identity-mismatched, or provenance-deficient inputs fail closed.

## Relationship and registry identity

Stable relationship identity binds the logical Definition Set identity plus the exact Engineering Binary digest. Binary revisions therefore remain independently governed; a corrected Definition Set revision for the same binary may supersede the earlier relationship without destroying history. Relationship revision binds exact Definition Set/XDF, decision, instruction, provenance, source role, lifecycle, and supplied publication metadata.

Registry Snapshots are immutable canonical collections of relationship revisions with append-only receipts. Pure exact-digest lookup returns one active relationship, multiple/conflict, none, or invalid. This is a domain proof, not application runtime integration.

## Atomic publication, receipt, replay, and stale state

Publication returns either a complete new Snapshot, relationship, and receipt or a rejected result whose prior and resulting Snapshot preserve the same immutable state. Instructions bind an expected Snapshot identity; advanced state rejects stale writes. Reapplying an already-recorded exact instruction is an idempotent no-op with the existing relationship and no duplicate history.

## Supersession and revocation boundary

Supersession retains the old relationship as `superseded` and activates the accepted correction. Destructive overwrite is impossible. Revocation is deliberately not implemented in this slice because non-accepting decisions cannot create publication instructions; a future separately governed lifecycle instruction must preserve inactive history.

## Domain separation and exclusions

Applicability qualification does not establish stock authenticity. Original and MapSwitch roles remain provenance only. Duplicate XDF bytes may support independent ROM relationships without authority transfer. The 133 contained Definition conflicts remain unresolved and excluded by the downstream calibrated-intent gate.

No filesystem registry, production data, Supabase, runtime wiring, equation execution, Native Vehicle Data, WP-005.1, UI, or real BMW cohort publication is included. N54 remains only the documented likely future first cohort.
