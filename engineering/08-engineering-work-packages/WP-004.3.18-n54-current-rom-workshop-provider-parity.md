# WP-004.3.18 — N54 Current-ROM Calibration Workshop Provider Parity

Status: implemented for controlled development preview; Founder localhost review pending

Authority boundary: this work exposes only the four already-governed current N54 layouts. It creates no applicability decision, Stock claim, semantic Knowledge, production vehicle identity, upload path, mutation, recommendation, or flash capability.

## Objective and architecture

I8A0S, IJE0S, IKM0S, and INA0S now use one server-side provider algorithm:

selected development ROM → immutable fixture descriptor → governed layout/Definition Set/relationship → exact Original and MapSwitch binaries → qualified Dataset pair → qualified comparison → generic Workshop View Model → Explorer/Grid/2D/3D.

Each descriptor explicitly binds its XDF and binary filenames, roles, fixture identity, provenance, and limitations. Runtime filenames are not inferred. Descriptor construction verifies the exact governed Definition Set revision and source digest, ROM layout, active relationship, and both binary software identities.

## Selection and disclosure

The development-only `previewRom` search parameter accepts exactly `I8A0S`, `IJE0S`, `IKM0S`, or `INA0S`. Absence deliberately retains IJE0S as the documented compatibility default. Unknown, case-altered, or Legacy values return an explicit unavailable preview and never fall back. The page identifies `Development Evidence Preview — <ROM>` and states that the Evidence is not derived from the selected vehicle.

## Cache and safety

The memoization key binds Dataset, comparison, and discovery contract versions; applicability snapshot; ROM layout; Definition Set revision; source artifact digest; and both binary digests. All four cache keys, Dataset pairs, and comparison identities are distinct. Warm loads are deeply deterministic. A descriptor combining IJE0S authority with an INA0S modified binary fails closed. Legacy and unknown selectors cannot materialize a Workshop.

## Performance observations

In the focused clean run on the development host, approximate first loads were I8A0S 13.8 s, IJE0S 12.1 s, IKM0S 11.7 s, and INA0S 11.6 s. Warm memoized loads were 10 ms, 10 ms, 4 ms, and 6 ms respectively. Concurrent full-regression contention produced slower clean observations and is not an identity input or product performance guarantee.
