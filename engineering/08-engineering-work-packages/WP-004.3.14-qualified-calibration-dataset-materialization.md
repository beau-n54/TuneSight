# WP-004.3.14 — Qualified Calibration Dataset Materialization

## Purpose

This work package creates one reusable, immutable Calibration Dataset for one exact Engineering Binary through the existing governed chain:

`Exact Binary → qualified layout discovery → binary membership → active applicability → exact Definition Set → qualified extraction → engineering conversion → complete Dataset`

The Dataset answers which engineering values are encoded. It does not establish what each parameter means or whether any value is desirable.

## Authority chain and atomicity

Materialization requires an exact byte-bound Engineering Binary Identity, one exact qualified discovery candidate, successful binary-to-layout membership, one active qualified applicability relationship, the exact Definition Set Revision, and a complete source-bound Definition universe. Failure before those gates returns `invalid`, `discovery_failed`, `membership_failed`, or `authority_unavailable` with no Dataset.

After authority succeeds, every Definition receives one immutable record. Individual extraction or conversion failures create explicit unavailable records and a `dataset_partial` result rather than a half-built or misleading Dataset. A Dataset with no unavailable Definitions is `materialized`.

## Dataset request and identity

The immutable request binds exact bytes and identity, all internal observations, qualified discovery and applicability registry Snapshots, membership authorities, source role, provenance, optional independently qualified ECU-family Evidence, and the Dataset contract.

Dataset stable identity binds the exact binary digest, discovered ROM Layout, qualified relationship revision, Definition Set Revision, and discovery/extraction/conversion/Dataset contract revisions. Registry Snapshots, discovery and membership revisions, Definition results, summary, and provenance participate in the Dataset revision. A new binary digest always creates a distinct Dataset identity even under the same layout and Definition Set.

## Definition record

The complete Definition universe is deterministically ordered by Definition Revision. Available records retain source display metadata without semantic promotion, stable identity and revision, source binding, scalar/1D/2D dimensions, raw Evidence, engineering Evidence, units, exact offsets, raw and engineering values, per-cell trace, equation identity/revision, axes, exact binary digest, ROM Layout, relationship authority, findings, and provenance.

Availability states include qualified and identity conversion, extraction unavailable, unsupported or malformed conversion, invalid numeric conversion, missing equation, representation conflict, structural invalidity, authority unavailable, and other explicitly unavailable conversion.

## Axis and value representation

Values retain scalar, ordered 1D, or row/column ordered 2D shape. Cell trace binds every engineering value to its raw value and exact byte offset.

Each axis remains independently represented with its axis identifier, outcome, equation source and revision, units, raw values, engineering values or literal labels, offsets, finding, and provenance inherited through its engineering Evidence. X and Y are never collapsed and semantic labels such as RPM or load are not inferred.

## Unavailable and conflicting Definitions

Unavailable records preserve the exact Definition and source binding, failed stage (`extraction`, `equation_parse`, `conversion`, `authority`, `structure`, `representation`, or `other`), explicit state, findings, any successfully produced raw Evidence, and provenance. Nothing is silently omitted.

Representation conflict is a first-class record. No equation, unit, or source representation is selected automatically. The current admitted N54 cohort has zero representation conflicts but the generic model preserves them for future qualified families.

## Summary

The immutable summary reports total, available, identity-converted, unavailable, and conflicted Definitions; scalar/1D/2D counts; available axes; represented units; represented canonical equation forms; and unique findings. These are descriptive counts only.

## Dataset reuse and comparison

The Dataset is the reusable domain object for later comparison, Workshop browsing, Knowledge binding, recommendation, and editing layers. This slice implements only comparison reuse. `compareQualifiedCalibrationDatasets` consumes stored engineering Evidence without rereading binaries or rerunning extraction/conversion. It preserves the existing qualified comparison identity, revision, Definition outcomes, cell deltas, axis comparisons, regions, and summary semantics when the same roles and provenance are supplied.

No cache or persistence is introduced.

## BMW-wide and MG1 compatibility

The Dataset engine has no N54 identifiers, platform branches, or closed engine enum. Any future qualified Definition Set can flow through the same contracts. Missing units, unavailable axes, unsupported conversions, representation conflicts, and differing qualified provenance are permitted and explicitly represented rather than prohibited globally.

## Exclusions and truthfulness

Source role remains separate and does not establish Stock authenticity. Titles, descriptions, categories, equations, and values do not become Calibration Knowledge semantics. The Dataset makes no quality, safety, aggressiveness, recommendation, Suggested Calibration, or Working Calibration claim.

This package adds no Supabase, persistence, filesystem cache, runtime upload, API route, dashboard, Analysis, Calibration Context, Workshop UI, Native Vehicle Data, WP-005.1, flashing, Knowledge Registry mutation, or deployment behavior.

## Completion condition

Complete when deterministic tests prove request and Dataset identity, exact-byte binding, every authority gate, atomic failure, complete Definition representation, scalar/1D/2D trace, axes, units, unavailable and representation-conflict records, summary counts, deep immutability, all four current N54 Original Datasets, IJE0S MapSwitch and newly modified Datasets, same-layout/different-digest identity, direct-versus-Dataset comparison consistency, BMW-generic structure, and relevant repository regressions.
