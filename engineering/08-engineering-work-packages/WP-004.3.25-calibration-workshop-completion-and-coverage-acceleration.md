## Subscriber Calibration loading implementation boundary

The localhost Workshop now accepts a subscriber-supplied calibration file through an authenticated, vehicle-owner-bound Node route. The route applies a 32 MiB bound, delegates container handling to the canonical Engineering Binary resolver, derives governed ROM/software observations, and admits a Workshop only for `EXACT_DEFINITION_COVERAGE`. Candidate, recognized-without-Definitions, discovery, conflict, invalid, and Dataset-materialization failures remain explicit non-Workshop outcomes. There is no preview-ROM, family, nearest-ROM, or development-fixture fallback.

For the four published N54 identities, the uploaded binary is materialized as the immutable Current Calibration Dataset under its exact applicability relationship and Definition Set. Reference is independently materialized from the governed Stock Candidate; deterministic comparison and the existing generic Explorer/Grid/2D/3D View Model then consume those two Datasets. The uploaded digest participates in the Current Dataset and Workshop source identity. Raw bytes are discarded after materialization and are never included in the View Model.

Derived Dataset/comparison evidence is retained for at most 30 minutes in a bounded 16-entry process-local map behind a cryptographically random opaque token. Every read is bound to the authenticated owner and vehicle. This supports normal table navigation and hard refresh on the same localhost process without cross-user state. Process restart, multi-instance routing, or expiry ends the session and requires the file to be reopened; no Supabase schema or persistent upload storage is introduced.

Current-only presentation is not admitted in this slice because the existing Workshop View Model and visualization contract require a qualified pairwise comparison. All currently published N54 subscriber relationships have an independently materializable governed Reference, so useful admitted coverage is not blocked. A future generic single-Dataset View Model must represent Reference and every comparison-derived field as explicitly unavailable before a platform without responsible Reference can be admitted; the uploaded Current is never reused as its own Reference.

The provider is registry-driven rather than UI-platform-branched. B58 Gen1 exact markers are already recognized by the same identity boundary but remain `ROM_RECOGNIZED_DEFINITIONS_UNAVAILABLE`; no B58 Gen1 Tables are exposed. Later S58, B58 Gen2, N55, S55, S63, and future BMW support enters through governed identity, applicability, Definition, and Reference registries without a second Workshop UI path. This slice creates no publication side effects, editing, Suggested Calibration, DME read, or DME write authority.
