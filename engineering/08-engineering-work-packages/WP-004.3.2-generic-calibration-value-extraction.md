# WP-004.3.2 — Generic Calibration Value Extraction

**Status:** Implementation Slice — Founder Authorised

## Purpose

This slice establishes a platform-neutral bridge from an exact Engineering Binary and immutable XDF Definition Revision to deterministic raw Calibration Value Evidence.

## Generic Extraction Model

The extractor operates on canonical definition properties rather than BMW engine or ECU branches. BMW master-library folders provide current coverage and validation sources; they are not a closed platform enum or TuneSight's permanent support ceiling.

Coverage and authority remain separate:

1. source available;
2. structurally readable;
3. extraction-capable;
4. applicability unresolved;
5. qualified for an exact calibration only through later governed qualification.

## Address Space

Definition Revisions preserve declared base offset, subtraction mode and regions. Address translation uses checked safe-integer arithmetic. Negative, unsafe, out-of-region and out-of-binary results fail explicitly. No address is clamped or wrapped.

## Raw Evidence

Extraction Evidence binds one exact Engineering Binary digest to one exact Definition Revision identity, structural digest and source-binding digest. It preserves resolved addresses, exact offsets, raw integer values, dimensions, directly embedded raw axis values, datatype, width, signedness, endianness, findings and extractor contract version.

Raw encoded values remain distinct from engineering values. Units and inert equation source remain Definition context; this slice does not execute conversion equations.

## Supported Boundary

The generic reader supports integer datatype `0`, widths 8/16/32, signed and unsigned values, little and big endian, scalar, one-dimensional and two-dimensional packed layouts, explicit positive byte-aligned row/column strides, additive/subtractive base offsets and directly embedded axes.

External/static axes, negative or non-byte-aligned strides, unsupported datatypes/widths, ambiguous signedness/endianness, unresolved Definition identities and unsupported address layouts remain explicit.

## BMW Master Coverage

Validation runs structural and extraction-readiness assessment over every XDF currently discovered in the BMW master library, including N54, B58 Gen1, B58 Gen2, combined N55/S55/N13, N55E, S58 and S63 directories. New platforms remain admissible through governed source, definition and applicability pathways.

## Exclusions

This slice does not implement engineering-value conversion, exact ROM applicability, semantic Calibration Knowledge, Stock/Modified comparison, recommendations, editing, reconstruction, runtime integration, persistence, UI, Vehicle Interface, WP-005.1 or flashing.

## Completion Gate

Completion requires deterministic synthetic binary vectors, multi-family master-library coverage, canonical XDF regressions, relevant Calibration Knowledge and Engineering Binary regressions, TypeScript, focused ESLint, security/bounds audits and exact staged-scope validation.
