# WP-004.3.1 — XDF Definition Foundation

**Status:** Implementation Slice — Founder Authorised

## Problem

The legacy XDF parser uses regular-expression table discovery and source-order-derived identifiers. It cannot provide stable Definition identity, immutable structural revisions or bounded deterministic interpretation.

## Authoritative Scope

This slice establishes:

- immutable exact-byte XDF Source Artifact identity;
- stable derived Definition identity independent of filename, display metadata and table order;
- explicit unresolved and conflicting identity outcomes;
- immutable Definition Revision identity with separate structural and source-binding digests;
- bounded deterministic structured XML interpretation;
- structural capture of XDF version, tables, metadata, addresses, element widths, dimensions, axes, units, byte-order-related source attributes and inert equation source;
- explicit structurally interpreted, unsupported, invalid and applicability-unresolved boundaries.

## Identity and Revision

Source Artifact identity is derived from exact source bytes. Filename, provenance labels and source revision metadata do not establish source identity or Definition authority.

Stable Definition identity is derived only where a minimum structural locator exists. It is independent of table order, UI order, filename and mutable display metadata. Missing or duplicate structural locators remain unresolved or conflicting.

Definition Revision structural identity is domain-separated from Calibration Knowledge digests. Structural revision digest excludes mutable title and description metadata. An independent source-binding digest binds the structure to an exact Source Artifact.

## Qualification Boundary

Successful parsing does not establish ROM applicability, semantic validity or Definition authority. Every interpreted Definition remains applicability-unresolved until a later separately authorised qualification slice.

## Security Boundary

The parser rejects external entity and DOCTYPE declarations, malformed XML, invalid numeric ranges and excessive bounded input, depth, node, table, axis, attribute, metadata and equation sizes. Equation text is inert source data and is never executed.

## Explicit Exclusions

This slice does not implement:

- binary or map-value extraction;
- semantic or ROM applicability qualification;
- stock/modified comparison;
- recommendations or editing;
- binary reconstruction, checksums or export;
- runtime Tune-upload integration;
- schema, persistence, API or UI changes;
- Vehicle Interface, telemetry, logging, diagnostics or flashing;
- WP-005.1 Engineering Run Intelligence.

## Validation and Completion

Completion requires deterministic unit tests, real bundled N54 and B58 XDF structural interpretation, stable identity under unrelated insertion/reordering, canonical digest stability and sensitivity, malformed and hostile XML rejection, explicit unsupported outcomes, relevant Knowledge regressions, TypeScript, focused ESLint and whitespace validation.

Physical Founder validation for this slice consists of inspection of deterministic results from real repository XDF assets. It establishes structural interpretation only and makes no ECU semantic-applicability claim.
