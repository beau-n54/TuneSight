# WP-004.3.29 — Calibration Export Readiness

## Private Source Binary reconstruction lease

A successful governed subscriber admission now creates a seven-day private source lease before the transient raw upload is deleted. Source bytes and lease metadata use separate opaque random object identities in the existing private `subscriber-calibration-private` bucket. An opaque HMAC-scoped active pointer permits replacement cleanup without placing owner, vehicle, VIN, filename or ROM identity in an object key.

The lease binds authenticated owner, vehicle, Current Calibration identity/revision, Current Dataset identity/revision, ROM layout, relationship revision, exact binary digest, byte length and container type. Retrieval is server-only through the trusted client. A replacement removes the previous source and metadata. Expired leases are removed during bounded cleanup. Session creation failure revokes the newly persisted source. Working history may remain after expiry, but reconstruction requires an exact byte-for-byte re-upload; another digest cannot inherit the mutations.

No public URL, signed browser read, service-role browser access, raw-byte logging or indefinite retention is introduced. The existing direct signed upload remains transient and is still deleted after processing.

## BMW checksum and integrity authority discovery

All 68 active exact relationships were grouped from governed catalog evidence by family and disclosed ECU/DME family, container type and binary byte length. Repository search found descriptive checksum metadata but no qualified algorithm, region boundaries, stored integrity fields, excluded ranges, repair procedure, validation vectors or authoritative external-flasher checksum contract for an exact relationship.

Every relationship is therefore `CHECKSUM_UNKNOWN` and `EXPORT_BLOCKED_CHECKSUM_UNKNOWN`. No relationship is `CHECKSUM_NOT_REQUIRED`, validation-only, repair-qualified, container-required, EXPORT-qualified or FLASH-qualified. MHD, bootmod3, TunerPro and WinOLS references in the repository do not document authoritative checksum behavior and create no TuneSight authority.

No checksum implementation or integrity byte allowance was created. Calibration reconstruction continues to require zero unexplained changed bytes; future qualified checksum mutations must be separately identified and proven.
