# WP-004.3.9 — Qualified Applicability to Exact-Binary Calibration Extraction Gate

Status: bounded local domain implementation. No runtime, persistence, engineering-value conversion, comparison, editor, or production integration.

## Authority chain consumed

The gate consumes the existing chain rather than creating another applicability system:

`XDF Source Artifact → Definition Set Revision → ROM Layout Identity → governed review → Founder Decision → active qualified relationship`.

It joins that chain to an independently exact extraction chain:

`Engineering Binary digest → Definition Revision → deterministic raw extraction`.

Only one exact-active layout lookup may proceed. `none`, `multiple_conflict`, and `invalid` remain distinct fail-closed outcomes. No family, filename, directory, size, or closest-XDF fallback exists.

## Request and membership

An immutable request binds exact Engineering Binary bytes and identity, ROM Layout Identity, registry Snapshot, expected relationship identity and revision, Definition Set identity and revision, Definition Revision, and the qualified-extraction contract version.

The byte digest is recomputed. The exact binary must already appear as subordinate Evidence on the active relationship with compatible byte length and internal ROM identity. This admits the accepted N54 original and MapSwitch instances but does not infer membership for a new modified binary.

The Definition must bind the relationship's exact Definition Set and Source Artifact, appear in both the Definition Revision and source-binding manifests, reproduce its canonical structural/source digests, have derived structural identity, contain no representation conflict, and be extraction-capable.

## Qualified raw Calibration Value Evidence

Successful output preserves the exact binary digest, layout, registry Snapshot, relationship, Decision, instruction, authority pathway, Definition Set, Definition Revision, source binding, raw address and offsets, datatype, width, signedness, endianness, dimensions, raw values, raw axes, inert equation sources, raw-extractor contract, and provenance.

Definition applicability provenance remains `Definition Set Revision → ROM Layout Identity`. Value provenance remains `exact Engineering Binary digest → exact bytes`. Original and MapSwitch therefore share applicability but produce independently identified Evidence.

The output is raw Evidence only. It is not engineering-unit data, Calibration Knowledge, Stock/Modified classification, semantic interpretation, safety assessment, or recommendation.

## Failure states

Authority rejection occurs before extraction for binary identity mismatch, unqualified layout, relationship mismatch, unqualified binary-to-layout membership, Definition Set mismatch, non-membership, conflict, invalid structure, or unsupported extraction.

After applicability succeeds, bounds, address, datatype, or shape failure returns `extraction_failed` with the authority chain and raw extractor findings. It does not change the qualified relationship.

Current N54 is the only real cohort. Legacy remains unqualified even when the raw extractor could technically read its offsets; its 63 representation conflicts remain unchanged.

## Future modified-binary gap

A future modified binary requires a separate governed exact-binary-to-layout qualification record preserving its digest, container, byte length, internal identities and offsets, structural address-space compatibility, negative controls, provenance, and explicit conflict assessment. Same marker, size, filename, or family must never auto-qualify it.

## Exclusions and completion

No XDF or conversion equation is executed; equation source remains inert metadata. No Supabase, API, upload, Analysis, Calibration Context, Workshop, persistence, runtime, Native Vehicle Data, WP-005.1, comparison, recommendation, flashing, registry expansion, or source mutation is included.

Completion requires deterministic success for all four current N54 layouts, original/MapSwitch independence, exact digest and offset provenance, lookup-state separation, Definition membership/validity, wrong-ROM, Legacy, conflict, unknown-binary and byte-substitution rejection, extraction-failure separation, immutability, equation inertness, relevant regressions, TypeScript, focused ESLint, and whitespace validation.
